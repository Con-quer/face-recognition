## 二、项目背景与意义

### 2.1 背景

原始教程用三个脚本（`get_picture.py` / `train.py` / `start.py`）演示了"采集—训练—识别"的完整思路，代码直观、门槛低，很适合入门。
但在真实使用中暴露了几类问题：

1. 三个脚本各自独立，路径、参数、日志分散，改一个参数要翻三个文件；
2. 缺少数据质量控制，模糊、误检的图片会被当作有效样本存入训练集；
3. 划分验证集的逻辑重复执行会不断缩小训练集，且划分结果不可复现；
4. Windows 中文路径下 OpenCV 无法读写文件，程序会静默失败；
5. 窗口里的中文姓名显示为问号；
6. 没有任何自动化测试，改动代码后只能靠"跑一遍看看"。

### 2.2 意义

本项目把上述经验固化成一个**可交付、可维护、可复用**的完整工程：

- 对个人：形成一份可写进简历/答辩材料的完整项目，而不只是几个脚本；
- 对学习：把机器学习"数据—训练—推理"的抽象流程落到可运行的代码上；
- 对他人：项目可被同学直接克隆使用，文档齐全，无需口头交接。

## 三、项目目标

### 3.1 功能目标

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| F1 | 人脸样本采集 | 摄像头预览、按键存图、自动裁剪、模糊过滤、断点续编号 |
| F2 | 数据集管理 | 按类别建目录、校验姓名合法性、按比例划分训练/验证集 |
| F3 | 模型训练 | 基于 YOLO11-cls 训练多分类人脸模型，输出 `best.pt` |
| F4 | 实时识别 | 摄像头逐帧识别，画面显示姓名、置信度、Top-K、FPS |
| F5 | 环境自检 | 一条命令检查依赖、字体、摄像头、数据集状态 |
| F6 | 命令行入口 | 采集/训练/识别/自检/统计统一入口，参数可用 `--help` 自查 |

### 3.2 非功能目标

- **可用性**：新手按 README 在 30 分钟内完成第一次识别；
- **健壮性**：摄像头打不开、依赖缺失、数据集为空等异常给出中文提示而非堆栈；
- **可维护性**：模块单一职责、统一日志、配置集中；
- **可测试性**：核心逻辑不依赖摄像头与真实硬件即可测试；
- **可复现性**：固定随机种子，重复运行结果一致。

## 六、技术方案

### 6.1 技术选型理由

| 环节 | 选型 | 为什么这样选 | 替代方案 |
| --- | --- | --- | --- |
| 人脸检测 | OpenCV Haar 级联 | 开箱即用、CPU 实时、无需训练与额外权重 | YOLO 人脸模型（更准，但更重） |
| 人脸识别 | YOLO11-cls 分类模型 | 直接分类到"是谁"，流程最短，`yolo11n` 体积小 | 人脸特征向量 + 距离检索（可扩展新人） |
| 训练框架 | Ultralytics | 一行代码训练，自带数据加载、增强、曲线与混淆矩阵 | PyTorch 手写训练循环 |
| 界面 | OpenCV 窗口 | 零额外依赖，直接叠加检测框与文字 | PyQt / Tkinter 图形界面 |
| 中文显示 | Pillow + 系统字体 | OpenCV 自带字体不支持中文 | 预设文字贴图 |
| 测试 | pytest | 生态成熟，夹具机制适合隔离文件与摄像头 | unittest |

### 6.2 系统架构

```text
┌───────────────────────────────────────────────────────────┐
│ 入口层   main.py / scripts/get_picture.py|train.py|start.py│
│ 职责：命令行解析 → 生成配置对象 → 调用业务层                │
├───────────────────────────────────────────────────────────┤
│ 业务层   collect.py │ trainer.py │ recognizer.py           │
│ 职责：采集闭环 / 训练闭环 / 识别闭环                        │
├───────────────────────────────────────────────────────────┤
│ 能力层   camera.py │ detector.py │ drawing.py │ dataset.py │
│ 职责：摄像头、人脸检测、中文渲染、数据集与划分              │
├───────────────────────────────────────────────────────────┤
│ 基础层   config.py │ logging_utils.py │ gui.py │ cli.py    │
│ 职责：参数与路径、日志、窗口工具、命令注册                  │
└───────────────────────────────────────────────────────────┘
```

依赖方向单向向下：上层调用下层，下层不感知上层，因此每一层都可以单独测试。

### 6.3 数据流

```text
摄像头帧 → 灰度化 + 直方图均衡 → Haar 检测 → 取最大人脸
        → 从原始帧裁剪（避免把提示框裁进去）→ 清晰度过滤
        → dataset/train/<姓名>/face_XXXX.jpg
        → 按 20% 随机抽样移动到 dataset/val/<姓名>/
        → Ultralytics 训练 → runs/.../best.pt
        → 实时加载 best.pt，逐帧分类 → 画面叠加姓名与置信度
```

### 6.4 数据规范

| 项目 | 规范 |
| --- | --- |
| 目录结构 | `dataset/train/<类别>/`、`dataset/val/<类别>/` |
| 类别名 | 即姓名，≤32 字符，不含路径分隔符与 Windows 保留名 |
| 命名 | `face_0000.jpg` 递增；重复采集自动续编号，不覆盖 |
| 格式 | 默认 JPEG（质量 95），可切换 PNG |
| 数量 | 每人 ≥ 20 张；类别 ≥ 2；验证集占 20% |
| 质量要求 | 单人正脸、光线均匀、清晰（拉普拉斯方差 ≥ 阈值）、人脸边长 ≥ 60 像素 |

### 6.5 关键配置项

集中定义在 `src/facerec/config.py`，命令行参数可覆盖：

| 模块 | 关键项 | 默认值 |
| --- | --- | --- |
| CollectConfig | 分辨率 / 模糊阈值 / 最小人脸 / 验证集比例 / 目标张数 | 1280×720 / 40 / 60 / 0.2 / 不限 |
| TrainConfig | 预训练模型 / 轮数 / 尺寸 / 批大小 / 设备 | yolo11n-cls.pt / 30 / 224 / 4 / cpu |
| RecognizeConfig | 权重路径 / 镜像 / 置信度阈值 / 显示项 | `runs/.../best.pt` / 开 / 0.5 / FPS+HUD |

| 编号 | 风险 | 可能性 | 影响 | 应对措施 |

| 每学期/每阶段 | 复盘识别错误案例，补充针对性样本并重训 |
